## Correcciones locales

- Los fallos EACCES/EPERM del almacenamiento se traducen a MAILBOX_PRIVATE_STORAGE_PERMISSION_DENIED. El panel explica que debe repararse el acceso y permite reintentar. No se muestran rutas ni secretos en respuestas.
- Un fallo de permisos no invalida la referencia de caché ni provoca una redescarga innecesaria. Una vez reparado, se puede abrir el cuerpo conservado; los FAILED también admiten reintento. Se mantienen cifrado, sanitización, sandbox y comprobación de permisos.
- Los fallos temporales de validación de sesión/DB no desactivan permanentemente una suscripción válida ni descartan eventos de pedidos/visitas/waitlist como si hubiera una revocación. Se reprograma sin enviar hasta poder comprobar autorización. Una sesión realmente inválida sigue bloqueando. Este defecto se reprodujo con pruebas; no se presenta como la causa histórica demostrada del dispositivo inactivo.
- Preparación de guardias de acceso al almacenamiento para instalación/publicación y de un reparador administrativo de propietario/permisos, con inventario y recuperación de metadatos. No se amplía sudo ni se ejecuta la aplicación como root. El controlador instalado no se actualiza automáticamente.

No se cambiaron políticas de enviados/retención, campañas, categorías, claves o suscripciones. Se conserva «Notificaciones push» como único punto de configuración; no se reintroducen botones retirados. No se habilitan avisos de clientes de Correos.
