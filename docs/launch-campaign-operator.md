# Campaña de apertura: operación segura

Esta guía no ejecuta la campaña. El estado inicial de la nueva migración es `PENDING`, incluso si la Pantalla Clave ya estaba desactivada: instalar el código o reiniciar el servidor no manda correos.

1. Antes de desplegar, confirma que el procedimiento del servidor aplica la migración Prisma `20260924120000_launch_campaign_state` **antes** de arrancar el nuevo backend. El archivo `deploy.sh` del servidor no está en este repositorio; no supongas que lo hace. Haz una copia de seguridad y comprueba la base de destino antes de usar el flujo habitual `npx prisma migrate status` y `npx prisma migrate deploy` desde `cronox-backend` con el entorno de producción cargado. No uses `db push` ni `migrate dev` en producción.
2. Confirma en el entorno real `EMAIL_ENABLED=true` y que el buzón `SMTP_INFO_USER`/`SMTP_INFO_PASS` está configurado. No pegues credenciales en un chat ni hagas un envío de prueba dentro de esta tarea. La comprobación del panel solo valida configuración local, no conectividad ni entrega final del proveedor.
3. Entra como SUPERADMIN en **Admin → Pantalla Clave**. Si la pantalla está actualmente desactivada, vuelve a activar una pantalla válida de prerregistro. Revisa el número de destinatarios, pendientes, aceptados por SMTP y resultados inciertos. Si hay resultados inciertos, investígalos antes de armar: nunca los reenvíes a ciegas.
4. Pulsa **Armar campaña** y confirma. El estado debe pasar de `PENDING` a `ARMED`; esto todavía no envía nada. Puedes **Desarmar campaña** mientras la pantalla siga activa si necesitas posponer la apertura.
5. Para la apertura real, desactiva el interruptor principal de Pantalla Clave y confirma el aviso, o deja que venza la fecha programada. Solo una campaña `ARMED` pasa a `SENDING`. El servidor continúa el procesamiento aunque cierres la pestaña o se reinicie.
6. Vuelve al panel para comprobar el estado. `COMPLETED`, cero pendientes y cero inciertos significa que el proveedor SMTP aceptó todos los mensajes previstos; **no** demuestra que llegaron a la bandeja de entrada. Contrasta la aceptación con los registros del proveedor sin compartir datos personales. Si aparece `ERROR` o un resultado incierto, no reenvíes ese destinatario. **Continuar solo pendientes** excluye los mensajes ya reclamados y requiere una decisión explícita del SUPERADMIN.

Cada código es personal, restringido a la cuenta y de un solo uso. El botón del correo lleva a `/launch.html#<token>`; la página exige una pulsación para consumir el enlace, cuyo token se guarda solo como hash y vence a las 72 horas.
